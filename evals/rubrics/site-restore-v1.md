# 页面还原评分细则（E2E）

版本：1.1-draft（新增结构化红线严重度 criteria）。新评测使用此版本；历史 run 保留其冻结的 `site-restore-v1.0-draft` 标记，不回填新字段或重评分。所有评委在评分前先阅读 [评测方案](../specs/site-restore-v1.md)。评分对象是最终 `restored/` 项目在固定视口和状态下的实际呈现与行为，不根据文件数、代码长度、框架选择或生成过程加分。

## 通用等级

| 分数 | 定义 |
| ---: | --- |
| 0 | 缺失、不可用，或与参考/任务根本不符；严重错误导致目标无法完成 |
| 1 | 只有少量局部相似；主要结构/行为明显错误，无法作为有效还原 |
| 2 | 部分可用；核心意图可辨认，但存在显著偏差、缺失或不稳定 |
| 3 | 整体忠实且可用；主要区域和要求满足，仅有次要差异 |
| 4 | 高度忠实、完整、稳定；关键视觉层级、细节和状态均与可见证据吻合 |

若 case 标注某维度不适用，记录 `N/A` 和原因，并在总分中按剩余权重比例归一化。不可因信息缺失把“无法观察”打成 0；若无法确认是 `N/A` 还是失败，标为待仲裁。

## 维度 Rubrics

### 1. 视觉结构与布局（`layout`，25%）

检查：区域数量与顺序、主次层级、容器宽度、对齐、留白、首屏构图、元素相对尺寸、滚动分区。

| 分数 | 锚点 |
| ---: | --- |
| 0 | 主体结构不存在或完全不同，页面用途无法辨认 |
| 1 | 只还原单个局部；主区域、层级或排列大幅错位 |
| 2 | 主要区域存在，但比例、顺序、对齐或密度有明显偏差 |
| 3 | 主要结构、层级和比例接近；少量间距或次要区域偏差 |
| 4 | 关键区域、比例、对齐、留白与首屏构图均高度吻合 |

### 2. 视觉样式与细节（`style`，20%）

检查：颜色、字体层级、字重、圆角、边框、阴影、图标、图像比例/裁切、媒体和控件外观。参考素材可取得而产物以色块、占位字或静态画面代替时，按可见偏差扣分；素材确不可得时，评价替代质量与已记录的限制，不因素材不可得直接扣满分。

| 分数 | 锚点 |
| ---: | --- |
| 0 | 样式系统与参考冲突，或无有效样式 |
| 1 | 颜色/字体/控件风格大多不符，细节粗糙 |
| 2 | 大体风格可辨，但多项关键 token、对比度或图像处理不一致 |
| 3 | 主要 token 和控件风格匹配，少量细节不同 |
| 4 | 主要 token、组件细节、图像处理和状态样式均一致 |

### 3. 内容与组件完整性（`content`，15%）

检查 case 标注的关键区域、文案、数据项、组件和信息层级。只对参考/任务中能确认的内容评分；额外的无依据业务事实同时按证据忠实度判断，严重虚构触发红线。

| 分数 | 锚点 |
| ---: | --- |
| 0 | 关键内容与组件基本缺失 |
| 1 | 多数关键项缺失、误写或层级错乱 |
| 2 | 核心内容在，但遗漏多个重要项或出现显著替代内容 |
| 3 | 所有关键项覆盖，次要遗漏或细节偏差有限 |
| 4 | 关键与次要标注项完整，层级和文案均准确 |

### 4. 交互与状态（`interaction`，20%）

每个 case 的交互清单必须在运行前冻结：动作、前置状态、期望反馈、是否关键。只检查有证据或任务明确要求的行为；静态参考看不到的行为不当作 ground truth。

| 分数 | 锚点 |
| ---: | --- |
| 0 | 所有核心动作不可用或页面崩溃 |
| 1 | 只能触发零散动作，无合理反馈或状态逻辑 |
| 2 | 部分核心动作可用，但存在明显失效、状态错乱或反馈缺失 |
| 3 | 所有核心动作可用并有合理反馈；次要状态有轻微缺陷 |
| 4 | 标注动作与状态完整、稳定且反馈清楚；键盘/焦点行为在适用时正常 |

### 5. 证据忠实度（`fidelity`，10%）

评分材料应包含“可见事实 / 用户明确要求 / 合理推断 / 不可判定”标注。判断页面是否把推断保留为设计选择，是否把未知业务事实包装成确定内容。

| 分数 | 锚点 |
| ---: | --- |
| 0 | 多项重大编造事实被呈现为已确认，误导页面含义 |
| 1 | 多个关键断言无证据，且没有留出不确定性 |
| 2 | 存在一些无依据细节，但未改变主要业务含义 |
| 3 | 事实基本可追溯；推断有限且未伪装成事实 |
| 4 | 所有重要内容可追溯；未知项被克制处理，推断不越界 |

### 6. 响应式与运行稳健性（`robustness`，10%）

固定至少一个桌面视口；仅当 case ground truth 指定窄屏行为时，才按窄屏打响应式分。检查加载、空白、水平溢出、遮挡、字体/资源失败、控制台致命错误。

| 分数 | 锚点 |
| ---: | --- |
| 0 | 无法加载或主要内容被破坏 |
| 1 | 多处溢出/遮挡/崩溃，核心路径不稳定 |
| 2 | 可加载但存在显著布局或运行问题 |
| 3 | 稳定可用，仅有局部不影响任务的问题 |
| 4 | 指定视口均稳定，无显著溢出、遮挡或运行错误 |

## 评分与证据记录

每个维度保存：`score (0–4)`, `evidence`（截图区域/交互步骤/事实 ID）, `reason`（1–3 句）, `redline`（如触发，列规则 ID）, `confidence`（high/medium/low）。Judge 不得看到实验组名称、文件夹名、模型名或系统提示差异；统一截图命名并打乱顺序。

加权总分：`100 × Σ(weight_i × score_i / 4) / Σ(applicable weight_i)`。硬门槛独立于加权总分，不能被高分抵消。

最终 E2E 的六个红线 ID、UI 触发条件、证据和 S0–S3 影响锚点见 [红线 criteria 与严重度](../specs/site-restore-v1.md#红线严重度与判定算法)。红线结果必须按 `E2ERedlineAssessment/v1` 输出；`pass` 只能搭配 S0/S1，`fail` 只能搭配 S2/S3；`unknown` 与 `not_applicable` 不得伪造严重度。Loop finding 的 `blocking`/`obvious`/`minor` 不适用于最终 E2E。

## 错误分类 taxonomy

可多选，按 case 计数：`layout_hierarchy`, `spacing_geometry`, `style_tokens`, `asset_crop_placeholder`, `missing_content`, `unsupported_fact`, `interaction_missing`, `interaction_state`, `responsive_overflow`, `runtime_failure`, `instruction_contract`, `other`。其中 `asset_crop_placeholder` 也涵盖可取得素材被占位、静态替代的偏差。新增类别须记录定义与版本，历史结果不静默重标。
