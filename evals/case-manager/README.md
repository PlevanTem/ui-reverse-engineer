# Case Manager

本地评测样本管理工具。它直接读取和写入 `../cases.yaml`，不上传数据、不调用外部 URL 分析服务。

## 启动

```powershell
cd evals/case-manager
npm install
npm run dev
```

在浏览器打开 Vite 输出的本地地址，工具会从 `../cases.yaml` 自动载入内置样本集。新增、修改和删除操作先保存在浏览器草稿；首次打开时点“保存”会导出 `cases.yaml`。也可点“打开数据集”连接本地文件并允许写入，之后点击“保存”即可直接写回；或导入 YAML 文件。

若浏览器不支持文件句柄 API，“打开数据集”会退化为导入；保存会下载文件，需要手动替换原数据集。

## 功能

- 样本库：按文本、UI 类型、任务类型、难度和状态筛选；点击行查看详情。
- 案例：创建、编辑、删除；技术栈和关键词以列表保存；未知 URL 为 `null`，未知技术栈为空列表。
- 类型：分别维护 UI 页面类型和逆向 task 类型。稳定 ID 不随改名变化；被 case 引用的类型只能归档。
- 统计：展示案例数、可评测数、UI 类型、task 类型、难度与技术栈分布；已归档案例不纳入分布。
- 数据保护：编辑自动留在当前浏览器的 `localStorage` 草稿中；不打开文件或点击保存不会覆盖 `cases.yaml`。

## 数据口径

字段约束见 [`../case-schema.json`](../case-schema.json)，样本数据见 [`../cases.yaml`](../cases.yaml)。当前有 7 个页面还原草稿案例；它们来自用户提供的 URL，尚未冻结评测截图与素材，因此不能直接视为可运行评测集。技术栈用列表记录高层模块（如引擎、图形 API、Shader、后处理、交互和性能架构），不把函数名、参数值、单个资源或模块清单当作栈标签；证据栏保留必要依据，未知框架和样式库留空。难度标签用简单 / 中等 / 困难；布局密度、交互复杂度、素材完整度、参考歧义和响应式范围只作为悬浮信息中的分级指引，不要求逐项录入。导入 Schema v1.1 数据会升级到 v1.2，保留三档难度、丢弃旧的逐项难度字段。工具不会因 URL 存在就自动猜测技术栈；只保存用户确认或有分析证据的技术。
