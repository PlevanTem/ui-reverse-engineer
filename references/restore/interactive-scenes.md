# 交互玩法、3D 与动画的实现参考

本文件说明如何把已观察的动态场景实现出来；阶段、降级与停止由 [SOP](../restore.md) 控制，数据格式由 [接口](interfaces.md) 控制。

## 玩法模型

采用 Robert Nystrom 的 [State](https://gameprogrammingpatterns.com/state.html) 与 [Game Loop](https://gameprogrammingpatterns.com/game-loop.html) 视角，分开理解输入、状态更新与渲染反馈。简单场景可用少量状态，不必引入通用游戏框架。

在 [brief](../restore-brief-template.md) 中记录输入落点/路径/持续时间、允许操作、状态转换、反馈、完成条件、重复操作与重置。区分点击和拖动，检查拖动松手是否误触点击、动画期间输入、下一轮、指针取消和视口改变后的命中。只实现已观察或用户要求的规则，未测边界标未知。

入口动作之后继续沿关键路径取证，不把首个可玩画面当作完整玩法。对游戏或长期运行场景，至少区分：准备/教学、核心循环、目标推进、奖励或升级、失败、重试/复位、持久化/解锁/终局（目标确有这些状态时）。用 `InteractiveScene/v1.transitions` 为每段写独立 transition；现有 Schema 已能表达 precondition、feedback、terminal state、repeat/reset 与 evidence，因此不为单个案例新增字段或服务层。

对所有可见进度分母建立“声明 → 生成条件 → 完成条件 → 终态反馈 → 复位/持久化”的可达性表。目标页未实际走通的内容保持 `unknown`；候选中不可达到的目标不是视觉小差异，而是状态模型缺陷。相同文本不等于相同机制，相同机制名也不等于相同节奏、数量和失败条件。

运行工具生成报告时，输入事实写入冻结契约的 `interactive_scene`（见 [Schema](interactive-scene.schema.json)），再由 renderer 生成 brief；实现残差写入 assessment。不要只手改生成的 brief，否则重新报告会覆盖它。

handler 存在、自行新增的计数标签、脚本调用成功不能单独证明玩法还原；需看实际画面、位置/几何变化及可观察状态。采用相同入口、重置后的固定输入或公开可用种子复现场景；不可控物理/随机差异记录范围，比较结构、动作顺序和终态。

## 资源与渲染

建立“可见物体 → 模型/纹理/动画/音效 → 加载器/解码器 → 渲染参数”映射。引擎名相同不保证相似，关键模型、相机或光照错误会主导画面偏差。

| 对象 | 核对内容 | 实现方向 |
| --- | --- | --- |
| GLB/glTF | 层级、比例、轴、材质、动画轨道、外部引用、压缩扩展 | 对实际资源运行 `inspect-gltf.mjs`，再用 viewer/场景核对；检查文件不证明线上可见用途 |
| 解码依赖 | Draco、KTX2/Basis、Meshopt 及加载的 decoder | 配置兼容加载器并本地化依赖；不能因解码失败直接用方块代替后声明达标 |
| 相机与空间 | 投影、FOV、目标点、距离、尺度、初始角度、限位 | 用多个角度的投影尺寸和遮挡关系约束参数 |
| 材质与光照 | base color、normal、roughness、环境、阴影、色调映射、色彩空间 | 有源码/材质则提取值；否则通过对照迭代，明确估计 |
| 动画 | clip、姿态、时长、缓动、过渡、触发、音画同步 | 优先复用有效 clip；重建时匹配关键帧、动作顺序与终态 |
| 命中 | 坐标转换、物体、遮挡、容差、相机变化 | 按已确认技术选 raycasting 等方法；平面旋转不能代替空间旋转与命中关系 |
| 物理与过程几何 | 切割、碎片、碰撞、UV、堆叠、复位 | 分开核对几何变化、运动和规则，按可见行为选程序几何、物理或确定性动画 |

Three.js 的 [GLTFLoader](https://threejs.org/docs/pages/GLTFLoader)、[动画系统](https://threejs.org/manual/pages/animation-system.html) 和 [Raycaster](https://threejs.org/docs/pages/Raycaster.html) 是实现参考，仅在 case 证据支持时采用。相对 URI、worker、WASM、模型纹理和 decoder 都须随本地项目验证，取得单个 GLB 不等于资源齐全。

## 动态对照

在同一初始状态、视口、落点和路径下，对照准备态、动作中段、接触/转场、终态与复位。保留采样时间和迟到值；截图会扰动时序，不能把请求的 80 ms 当成精确帧。短暂反馈可用视频或更密集的局部采样。

成对对照必须使用同语义状态：目标竞速倒计时只能与候选竞速倒计时比较，候选自造的升级卡、测试入口或遥测状态不能替代目标证据。程序检查用于证明入口、事件和数据可执行；视觉与行为等价仍由目标/候选的匹配轨迹判定。

修复任务应有可检验原因，例如“方向正确但投影偏小，调整相机距离”或“贴图齐全但发灰，核对色彩空间/光照”。玩法错误先修状态转换与命中，再调外观；质量判定沿用现有 Criteria 和 E2E。
