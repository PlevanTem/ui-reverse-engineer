# Restore 执行流程

直接 URL 的自动推导、合同冻结、brief 投影与已授权登录统一见 [Harbor 自动入口](harbor/automation.md)。叙述事实只存 contract.task_description；brief 与 Data Factory task 均从合同生成。

本文件是 `--restore` 的领域执行 SOP。Harbor 0.25.0 负责 task、trial、multi-step、停止、独立 verifier、ATIF 与 regrade；本文件只定义 Restore 的取证、实现、比较和验收语义。低层命令见 [`restore/interfaces.md`](restore/interfaces.md)，运行中的三类视觉评分见 [`restore/criteria.md`](restore/criteria.md)，最终交付验收见 [`../evals/restore.md`](../evals/restore.md)。

## 目标与边界

目标是依据可观察证据，交付一个可运行、可修改、尽可能忠实的 `restored/` 项目。Restore 不是网页存档，也不要求复制原站源码或技术栈。

- 观察到的页面内容、状态、素材和行为可以作为实现依据。
- 未观察到的业务事实、隐藏逻辑和外部副作用不得包装成已确认事实。
- 只读访问和本地实现属于默认范围；远端提交、消息或状态变更必须由任务明确允许。
- 缺少浏览器、素材或独立评委时，继续完成可验证部分，并把其余项标为未知或 `incomplete`。

## 流程

### 0. 判断复杂度与可用能力

按还原目标选档，不沿用 case 的 `easy` 标签：含扫描模型、动态几何/物理、空间相机或多阶段玩法的页面，通常需要 refined / complex；先说明范围、档位、预算和检查点。

分别确认宿主浏览器、Node/Python Playwright、公开源码/资源读取、文件证据保存、Loop 诊断/成对复核和最终独立 E2E 的可用性。按已暴露工具选择路径，不绑定固定工具名或本机包；Node 缺包后检查其他已提供能力。没有 adapter 文件不等于没有独立 evaluator，独立评分结果可按接口录入；实现者不得将自己标为独立评委。

过程记录只接受 Harbor agent 生成且由官方 validator 通过的原生 ATIF-v1.7/v1.8。保留 producer 实际版本，不改标签伪升级。ATIF 缺失或非法时保留 artifacts，但不得从 Restore ledger 补造轨迹。四维过程评估只读取 ATIF 与 Harbor artifacts，不改变本节的页面验收职责。

实现、评测和报告是三个职责边界：实现者只消费生成白名单并修改 `restored/`；评测器读取冻结参考和候选产物，生成测量、Diff 与判定；报告器只校验并汇总已有事实源。即使三个职责在同一宿主执行，也不能让实现上下文读取评测集的源码证据或让实现者自称独立评委。

导航超时或服务报错后，先读取实际标签的 URL、标题、DOM 地标和截图。按目标主体判断是否被挑战页替代；遥测、分析或其他域名的 403/Cloudflare 报错不能证明目标站被拦截。对可用替代路径做有界检查，记录实际失败点，不盲目重试。

### 1. 冻结任务

记录目标 URL、页面、视口、可达状态、关键区域、交互步骤、运行门禁、允许的副作用、参考证据和未知项。参考截图、录屏、资源和契约写入哈希；冻结后不得在同一 run 中替换。

`cases.yaml` 中的技术栈、源码和历史证据属于评测数据面，只用于数据集分析、分层统计和事后审计，不进入生成上下文。实现者只读取由冻结契约投影出的 `RestoreGenerationInput/v1`（旧合同）或 `v2`（优化合同）；默认 `fixture_only` 模式只暴露 case ID、视觉/交互夹具、允许资源和输出约束，并过滤 `source` 证据及源码类资源。若任务明确允许 source-assisted，还须在新 run 中把策略冻结为 `source_assisted`，不能临时放开。

先选择不超过五个高影响视觉锚点，但中段、页尾和必要交互仍须覆盖。动态要求必须有时间序列、视频或操作前后状态；单张截图不能证明完整动态。

对玩法、3D 与显著动画，读取 [交互场景实现参考](restore/interactive-scenes.md)，在 brief 中记录状态转换、输入轨迹、可见反馈和重置路径。追踪实际加载的第一方入口、模型、纹理、动画、音频及解码依赖；对应技术取证沿用 [技术栈 SOP](technology-stack-analysis.md)。第三方作者说明只补充背景，不能替代当前画面与行为证据。

当入口会进入游戏、编辑器、配置器或其他持续交互系统时，冻结范围不能停在“按钮可点击”或首个过场。须从入口继续观察到可重复核心循环，形成关键路径状态图：入口与准备态 → 教学/首个有效输入 → 核心目标推进 → 成功或失败反馈 → 重试/复位 → 已观察的持久化、解锁或终局。每个画面上声明的目标总量、等级、生命、货币或进度必须对应可达条件和终态证据；未走通的链路标为 `unknown` 或部分实现，不能用候选自行产生的计数器、DOM 遥测或代码存在替代目标页的同语义证据。冻结后发现关键路径漏项时，不在原 run 中补写契约；保留原账本，按 [Restore 接口的 `refreeze`](restore/interfaces.md#最短运行链) 从显式新合同来源建立重新冻结的 run。

冻结的 applicable C1/C2 必须关联参考截图，applicable C3 必须关联序列/视频；纯文本网页摘要不能作为完整视觉参考。确实拿不到某项时保留 unknown 并说明，不把缺证据改成 N/A。参考不可充分冻结时继续做源码、资源和可观察部分的诊断，交付须说明范围；不得以文本摘要伪造已冻结视觉任务。

### 1.1 准备与分块规格（新任务可选启用）

使用 [接口](restore/interfaces.md#优化规格与准备检查)的 `init-vnext` 建立优化合同。先 inspect，再写入可持续使用的规格，最后实现；初始模板有意不完整，不能直接冻结。旧合同保持原样，不在原 run 中补写新版字段。

Harbor `prepare` step 完成本节的检查和合同冻结；后续 step 只读取冻结合同与允许的生成输入。阶段结果写入 `/home/pwuser/restore-run` 并由 separate verifier 独立读取；格式通过不能替代最终验收。

1. 用视觉、真实输入、可用时的公开源码/样式/资源互相验证。覆盖必需状态和关键路径，记录已观察、推断和未知；阻塞未知不能以“后续再补”绕过准备门禁。先验证实际导航 URL；位于子路径的参考可使用相对路径 `.`，不能默认 `/` 仍指向当前页面。
2. 把设计 token、逐状态区域、参考框/坐标系、资源映射、任务依赖和验收引用写入合同的优化规格。优先做不可运行、主体缺失和核心路径问题，再修视觉影响大且成本低的偏差；优先级是工程判断，不是假装精确的收益预测。
3. 交互用输入事件、有限变量、guard、状态转换、关键帧/driver 和可观察不变量描述；详细取证方法见仓库内 [reverse-motion-skill](../reverse-motion-skill/SKILL.md)。表达式只保存声明，不执行任意代码，也不自动求解玩法。动画资产的 clip 时长不能直接当成页面实际播放时长；空间、时间和物理参数缺证据时保留推断。
4. 声音分别记录素材、BGM/SFX 触发、loop、重叠、重置和已知增益。网络加载、`play/start` 调用和实际可听输出是不同证据；音质与同步必须通过录音/监听验证。没有录音能力时继续验证事件和资源，最终声音验收保留 unknown。
5. 按 [资产布局](restore/asset-layout.md)选择资源与工具，保留已工作的引擎目录和依赖关系。先复用已确认可用素材；需要空间命中/旋转/形变时采用能承载它们的实现。工具仅在当前宿主可用时使用，不能把路由指南当成已安装的插件。
6. 执行准备检查，修复必需覆盖和资产完整性问题；拟做完整或正式配对验收时，先核对对应 rubric 的红线配置、最终评测输入资格及实际启动命令，再冻结并生成白名单输入与实施 brief。每轮只修一个偏差簇；几何诊断、完整路径回归和匿名成对比较各自保存证据。未知坐标系、缺少参考框或未声明容差不产生通过结果。

视觉匿名比较只消费目标要求和媒体；绑定、版本身份、路径、历史分数及修复者叙述留在控制器。独立评分与音频验收仍须另做；匿名比较不自动证明整个网站完成。接口与标准 Schema 只维护在 [interfaces.md](restore/interfaces.md)，最终效果/效率的比较协议见 [版本验收](../evals/vnext-acceptance.md)。

### 2. 建立版本轨迹

实现第一个可运行版本并记为 `v0`，采集与参考相同状态和视口的证据。按 C1 构图、C2 外观、C3 动态记录 0–4 分、门禁、自动检查和残差。缺证据写 `unknown`，参考明确不包含某项才写 `not_applicable`。`v0` 只是完整轨迹的起点，不是报告的唯一主角。

核心体验依赖空间旋转、命中、形变或动态几何时，初始实现须能承载这些行为；2D 示意图可以用于诊断，不能据此宣称完成 3D 还原。资源不可取得时先核查已提供的其他采集/导出路径，再记录替代方案及实际影响。

从 `v0` 起保存每个版本的产物哈希、证据、评估、自动检查、文件 Diff、义务分数变化、finding 增减、验证结论和 keep/revert/inconclusive 决策。未采用版本也保留在轨迹中，不能只报告“最佳版”。

### 3. 生成、评估、Diff 与有界修复

每轮只处理一个高影响偏差簇：

1. 写明问题、假设、改动范围、预期变化和必须保持的内容。
2. 生成候选版本并重新采集同状态证据，执行适用的静态和运行检查。
3. 计算相对当前最佳版的文件 Diff、义务分数变化和 finding 增减。
4. 以参考、当前最佳版和候选版做 A/B 与 B/A 比较。
5. 只有可见改善一致且没有关键回归时保留候选；否则回退或标记无法判定，但候选仍进入完整轨迹。

优先级依次为：不可运行或关键状态不可达、主体结构和核心素材、明显视觉偏差、次要细节。资源与实现技术是原因标签，不单独成为评分维度。

对持续交互系统，每轮还须检查“闭环可达”：目标页和候选页从相同语义入口出发，能否经真实用户输入到达相同类别的成功、失败、重试和后续进度状态。候选侧单独通过脚本、内部状态或自定义遥测，只能证明候选可运行，不能证明与目标等价。

跨导航、跨载具的深层路径需要拆段取证时，使用[接口](restore/interfaces.md#动态采集)定义的显式共享会话；默认 state 隔离不变，禁止用预载存档替代真实前置轨迹。

### 4. 停止

默认档位：

| 档位 | 有效执行时间上限 | 最多修复轮数 | 最终检查预留 |
| --- | ---: | ---: | ---: |
| ordinary | 30 分钟 | 3 | 3 分钟 |
| refined | 60 分钟 | 6 | 6 分钟 |
| complex | 120 分钟 | 9 | 12 分钟 |

达到目标、连续无明确改善、假设循环、预算耗尽、外部阻塞或失败时停止。交付最佳已验证版本，不为凑轮数继续修改。外部暂停只有在存在宿主起止证据时才从有效执行时间中扣除。

预算和轮数是上限，不是必须耗尽的配额。提前停止需要可核查原因：达到目标须满足 Criteria；阻塞须保存实际证据、尝试过的可用路径或不可用原因、剩余工作的处理结果，并通过 `RestoreBlocker/v1` 记录。冻结前无法取得必要参考时保留探索证据和未完成说明，不强行冻结。

Harbor trial 停止后不得通过 Restore CLI 重开同一 loop 或改写开始时间、停止原因、合同、ATIF 和 artifacts。用户要求继续时创建新的 Harbor task/trial，显式引用父 trial/task/contract/artifact hash，并把继承产物作为待重新测量的 baseline；不得继承父评分或把未验证候选冒充最佳版。

最终 E2E Judge 缺失只影响最终验收，不能单独停止可继续的 Restore 工作。若 Loop 的 measure/verify 本身缺少独立评委，可继续采集、程序检查和修复可观察缺陷；自查标 implementer，不能填造独立评分或 keep。真正无法继续复核时以对应 Loop 阶段的证据停止，候选保留作未验证版本，最佳版不被未经复核的候选替换。

### 过程沟通

由执行 Agent 主动发送用户可见进度；CLI 的 `progress` 只提供事实，不会自动替 Agent 发消息。启动、参考冻结、`v0` 初始测量、每轮生成/measure/diff/verify 决定及停止时均告知；持续工作每 60 秒内提供一次有内容的更新。

更新格式：`[阶段 / 版本 / 状态 / 进度] 已观察证据与当前差异 → 本轮假设与生成/修复事项 → 自动检查和测量 → 文件/评分 Diff → A/B、B/A 结果 → keep/revert/inconclusive → 剩余预算与下一步`。尚未得到的结果写待测；零修复轮时明确说明哪些步骤尚未执行及原因。停止报告分别列 Loop 原因、E2E 状态与剩余限制，不能用“报告已生成”替代质量结论。

### 5. 最终验收与报告

Loop 结束后，由独立 evaluator 对最终产物执行五维 E2E 和六类红线检查。Loop 分数不换算为 E2E 分数，E2E 发现问题也不会重写或重开已停止的 trial。继续工作需要新的 Harbor task/trial，并显式绑定父 trial 与证据。

最终报告从冻结契约、运行状态、事件账本、所有版本快照、Diff、自动检查、观察记录和最终评测生成。`report.json` 与 HTML 必须呈现 `v0 → vN` 的完整版本轨迹及每轮改善/回退依据；不能只展示首版和最佳版。人工审批单独保存并绑定报告与模板哈希。

## 完成检查

- `restored/` 可按记录的入口运行；
- 必需页面、视口、状态和交互均有证据或明确的未知说明；
- 持续交互系统的关键路径已覆盖核心循环、失败/重试及已观察的持久化或解锁；可见目标总量均有可达性结论；
- 关键资源与字体已核对，控制台和加载失败未被忽略；
- 全部生成版本、文件/评分 Diff、自动检查和 keep/revert/inconclusive 依据可追溯；
- 最终五维 E2E、红线、限制和校准状态已记录；
- 每个已执行 step 的 ATIF 已通过官方 validator；缺失或非法时明确关闭轨迹与训练候选资格，不从 Restore 记录补造；
- 使用 Restore archive/scratch audit 检查本 trial artifact 中的过程产物，记录扫描缺口与保留项；
- 未把推断、占位内容或未检查项写成事实。
