# `--restore` 自迭代还原：v0.1 历史提案

当前实现和决策以 [Restore v0.2](restore-v0.2.md) 为准。本文件保留旧提案和 UIR-0006 试点背景，不作为 v0.2 运行指南。

状态：**方案草案；单 case 人工编排试点已执行，自动控制器尚未启用**。版本：0.1（2026-10-13）。适用范围：`--restore` 的网站逆向复现；默认组合模式中的还原部分同样适用。本文规定拟实现的能力与顺序，不改变当前 [还原指南](restore-guide.md) 的运行要求。

当前实现接口见 [Restore v0.2](restore-v0.2.md) 和 [运行接口](restore/interfaces.md)；本提案及 [`v0.1 运行契约`](../evals/specs/restore-loop-contract-v0.1.md)仅用于追溯设计来源。跨方案版本决策仍由 [E2E 评测方案](../evals/specs/site-restore-v1.md)及 [Rubric](../evals/rubrics/site-restore-v1.md)负责。

## 1. 决策与问题

**要支持的决策：**给定一个可观察网站及其允许使用的资源，Agent 何时应继续修复、修复哪一处、何时回退、何时能够如实交付；跨 case 的 Skill 修订是否确实优于当前版本。

当前 `--restore` 已要求资源取证、实现和浏览器对照。UIR-0006 试点已冻结首页三状态和一轮目标修复，并生成可审阅报告；其余候选 case 仍未冻结，自动化采集和控制器未实现。单 case 的源码辅助成功不能证明跨站点或盲生成效果，因此不能把更多自主迭代直接等同于更高还原质量。

**产品目标**

1. 把“尽可能还原”拆成页面、区域、状态和操作步骤上的可检查义务。
2. 让每轮修改有证据、明确假设、前后比较和保留/回退决定。
3. 同时覆盖静态外观、动态行为及环境/个性化变体，避免单张截图导向的投机优化。
4. 对无法观察的事实返回“未知”，保留残差和限制，不制造完整复现的假象。
5. 让跨 case 的 Skill 改动通过现有配对 E2E 评测确认，而不是靠单 case 成功推广。

**非目标**：逐字复制原站源码或原技术栈；仅交付单 HTML；用一个视觉相似度数值证明网站等价；自动无限运行；把页面未暴露的行为推断为验收真值；本阶段改动 `--query`、`--design-md`、`--transfer` 的独立流程。

| 来源 | 采用 | 不直接照搬 |
| --- | --- | --- |

## 3. 两层循环

### A. 单 case 产物循环：修复 `restored/`

`冻结目标 → 观察与取证 → 首轮产物/基线 → 确定性检查 + 视觉诊断 → 排序残差 → 单轮聚焦修复 → 全场景回归 → 保留/回退 → 交付或继续`

每轮只选择一个可描述的偏差簇，例如“窄屏导航遮挡”或“切换模式后 3D 画面未更新”。允许一个偏差簇涉及多个文件；不要求机械限制单文件修改。选择优先级按**红线、用户可见重要性、证据充分度、修复成本、回归风险**排序。视觉分数改善不能覆盖关键交互失效。

### B. 跨 case 系统循环：修订 Skill、参考和 harness

先在开发集记录当前失败类型，修改有因果指向的指令或工具流程，再对同一 case 配对复测，并在封存集检查泛化和回归。版本比较沿用现有 spec 固定的 `gpt-6-luna` / `high` 等运行条件，不临时换模型。与产物循环分开记录版本，不能让一个 case 的评委反馈直接改写封存集规则。Skill 的触发测试仍不属于现有还原 E2E 评测范围。

## 4. 用户故事与功能要求

| ID | 要求 | 验收观察 |
| --- | --- | --- |
| R1 | 将输入 URL 与实际落地页、目标页面、视口、状态、动作和范围冻结为任务契约 | 每个被评分状态均可由独立运行器重现；验证页、跳转页与外链目标不会混同 |
| R2 | 主动从普通网站 URL 结合源码/资源与视觉观察取证 | 每条关键义务有来源、时间和置信状态；只加载却未用于目标区域的库不冒充还原要求 |
| R3 | 保留图片、字体、媒体、3D 资源和交互证据的映射 | 关键素材的可用性、用途、替代与差异可追踪；不限制项目文件结构 |
| R4 | 生成首次可运行基线并记录失败 | 首次分数及每个失败的页面/状态/区域可定位；没有参考证据时显示“未知” |
| R5 | 分层比较静态、动态和环境变体 | 不以单张首屏或单一总分决定下一轮；同一步骤有参考与本地配对证据 |
| R6 | 控制修复循环 | 每轮有假设、改动、前后指标、回归结果、保留/回退和停止原因 |
| R7 | 交付可审阅结果 | `restored/` 可运行；brief 与实际实现一致；残差、未覆盖状态和验证结果如实列出 |
| R8 | 验证 Skill 版本提升 | 使用现有 E2E Rubric 比较版本；报告配对差异、区间、红线和代表 case |

## 5. 任务规范与设计约束

**任务契约**由 case 元数据引用独立、版本化的 fixture，不把大截图或隐私数据塞进 `cases.yaml`。最少定义：目标和实际 URL、页面/视口、浏览器和显示环境、滚动/时间点、存储及语言初态、动作步骤及就绪条件、参考截图/录屏/结构证据、关键区域与行为、资源清单、允许遮罩项、未知项、各项证据来源与哈希。当前字段见[运行接口](restore/interfaces.md)；v0.1 草案不是活动 Schema。

**约束**

- 参考事实、推断、未观察与运行失败分别标记；未知不自动算通过或失败。
- 同一比较对固定浏览器、视口、设备像素比、字体、区域设置、初始数据与就绪条件。站点内容漂移时先重审 fixture，不暗中更新金图。
- 关键画面为 Canvas/WebGL、视频或动效时，契约应包含对应状态或时间序列；无法固定随机性时采用结构/行为与多个关键帧，不强用逐像素阈值。
- 主观评委与修复器角色分离；评分器和硬门槛在一轮实验中只读。任何评分口径修订须升版本并重跑基线。
- 页面或证据不可访问时保留可观察部分，明确 `blocked/unknown`，不凭第三方资源名称推断原站核心实现。
- 框架、文件数和是否单文件不计分；可运行性、资源与目标行为计分。

## 6. 质量门禁与停止规则

沿用[现有 E2E Rubric](../evals/rubrics/site-restore-v1.md)做**最终质量与版本比较**；逐区域/逐状态 Loop 诊断只用于**修复导航**，不与 E2E 分数合并。当前模块边界与适配器协议见[运行接口](restore/interfaces.md)。

一轮修改仅在以下条件同时满足时保留：硬门槛无新增失败；目标偏差有重复可见的改善；其他已通过的关键状态无实质回归；比较证据完整。证据不完整时标记 `inconclusive`，不得伪装成改善。对相近分数的候选，优先选择更稳定且更简单的实现。

停止于以下任一条件：全部适用红线与约定质量标准满足；连续两轮没有可信改善；达到事先写入 manifest 的轮次/时间/资源预算；剩余重要差异依赖不可获得的参考证据或素材。预算和数值阈值须在试点前填写并校准，本草案不把任意数字伪装为已验证标准。到达预算也可能是“未完成交付”，不能改称成功。

```text
references/

  restore-iteration-prd.md          # 本文：目标、范围、要求、实施决策

  scripts/restore/                  # v0.2 控制器、采集/诊断工具、报告生成器
  assets/restore/                   # 唯一单次 HTML 报告模板
  references/restore/               # 活动字段、命令、模块边界和数据流

```

单 case 交付至少有 `design_brief.md`、可运行的 `restored/`、参考/本地对照、逐轮决策记录和残差清单。当前单次报告由 [`scripts/restore/report.mjs`](../scripts/restore/report.mjs) 从结构化 run 数据生成 T0–T4、brief、JSON 和 HTML；模板唯一保存在 `assets/restore/report.html`，审批 JSON 绑定报告与模板哈希。v0.1 的并行 HTML、Schema 和重渲染器已退役，历史 HTML 保持静态可读。跨 case 版本报告继续使用 `evals/templates/report.md`。证据大文件、用户生成素材和敏感浏览器会话只存许可允许的本地位置；仓库保存可复现说明或脱敏摘要。

## 8. 分阶段执行计划

| 阶段 | 工作与交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| P0 任务真值 | 选静态内容、复杂交互、3D/动效各至少一个试点；冻结页面/状态/视口、素材与证据；记录不可复现项 | 每个试点都有至少一个完整静态状态；动态试点有可回放动作；fixture 有版本和哈希 |
| P1 基础比较器 | 实现契约校验、项目启动、固定环境截图、资源/控制台/关键交互检查及差异报告；先观察预期的失败 | 无改动重跑结果稳定；缺失证据返回 unknown；一次故意破坏能触发对应检查 |
| P2 视觉诊断 | 加区域化图像比较、人工标注的显著性和遮罩、盲评 Judge；校准与顺序/组名偏差测试 | 同一输出的自动诊断足够稳定；主观评分达到现有 E2E spec 的校准要求，否则仅作辅助 |
| P3 有界控制器 | 每轮生成一个修复假设、保存候选、全场景回归并保留/回退；输出残差与停止原因 | 至少三个异质试点都能展示可审计的轮次；硬门槛不被视觉分数覆盖 |
| P4 工具与 Skill 试验 | 将 REA 与已有浏览器取证在一个复杂 case 上比较证据增益/缺口；对 Skill 改动跑开发集与封存集配对 E2E | 有明确的增益或弃用理由；版本结论依据配对结果而非单站轶事 |

P0/P1 不依赖模型自动发起不同实验组：可以先摄入人工收集的产物。Harness/Plugin/Skill 的自动调用接口未核实前，不承诺完整无人值守管线。执行者在每阶段完成后更新对应文档和中英文 README，并按项目 `AGENTS.md` 做适当检查。

## 9. 风险、未决决策与验收

| 风险 | 控制办法 |
| --- | --- |
| 为了提高截图分数而牺牲交互或其他视口 | 关键行为硬门槛、全场景回归、封存状态和人工抽审 |
| 原站内容、字体、地域或随机 3D 状态漂移 | 固定环境与参考版本；记录不可固定变量；漂移需人工重审并升 fixture 版本 |
| 评委偏好某种实现或品牌 | 盲化方案、交换顺序、与人工配对校准；不看源码长短或框架名 |
| REA/浏览器取证缺口被误判为“没有行为” | 每项记录采集窗口与完整性；未请求、截断、附着前事件一律标为未知 |
| 迭代成本升高却无稳定收益 | 固定停止预算、逐轮改善账本、与一次生成基线配对比较 |

**本方案文档的验收**：主文档能说明目标、边界、两层循环、阶段与停止条件；配套契约能让工程实现者独立构建 runner 和诊断输出；所有待校准数字均注明提案状态；不宣称已完成任何试点或管线。

**实施效果的验收**：先看单 case 的修复记录是否可复现和回退，再看跨 case E2E 是否在红线不增加的条件下改善；差异区间跨零、评委未校准或样本不足时结论为“不确定”。
