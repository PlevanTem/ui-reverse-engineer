# `--restore` 逆向还原指南

当前自迭代执行规范见 [Restore v0.2](restore-v0.2.md)。需要评分细则时读 [视觉 Criteria](restore/criteria.md)，需要脚本和字段时读 [运行接口](restore/interfaces.md)。旧试点契约保留在 `evals/specs/`，仅供查阅历史结果。

`--restore` 交付可运行的网站还原项目。目标是复现参考中可观察的页面、资源、视觉细节、响应式布局、动效和交互状态。实现形式由目标决定：简单页面可以只有一个 HTML 文件；有多页、真实素材、复杂动画或 3D 场景时，使用必要的目录、资源和依赖。

## 1. 固定还原范围

- 确认目标 URL/输入、实际落地页、页面清单、关键视口和要复现的状态。平台资料页与其链接的外部网站分别界定。
- 浏览首屏、中段、页尾和关键路径；记录导航、点击、悬浮、滚动、键盘、表单、模式切换等可观察行为。截图/录屏无法显示的行为标为待确认。
- 为每个页面建立区域与状态清单，标出证据来源。对动态页面保存可比较的时间点、滚动位置和操作步骤。
- 若给定参考受登录、验证、区域限制或加载错误影响，记录实际可见状态和无法访问的范围；继续处理可观察部分。

## 2. 逆向资源与实现

- 按[网站技术栈分析 SOP](technology-stack-analysis.md) 从普通 URL 主动查看页面 HTML、实际加载的资源、公开源码映射、运行时和视觉载体。
- 建立资源清单：图片、图标、SVG、字体、视频、音频、3D 模型、纹理、着色器、数据与页面文案。逐项记录来源 URL/文件、页面用途、可用性和本地路径或替代方式。
- 优先将可取得且与目标一致的资源纳入项目并记录来源；若不可取得，按视觉证据重建或选择最接近的替代，并在交付说明中标出差异。不要在真实素材可取得时默认使用色块或占位文字。
- 分清页面自己的实现、第三方公共资源和仅被加载却未用于目标区域的依赖。原站所用技术可帮助理解实现，但不要求机械复制原技术栈；选择能稳定复现目标行为的实现。

## 3. 实现与交付

- 以区域、资源和状态清单组织实现，复现布局、排版、颜色、裁切、层级、细节、响应式行为、动效与交互反馈。
- 复杂视觉使用与证据相称的实现。Canvas、WebGL、3D、视频或逐帧动效是目标关键部分时，应实现对应动态表现；只有参考或环境确实缺少必要信息/资源时，才说明降级及差异。
- 将可运行项目放在 `reverse_output/{case_name}_{YYYYMMDD}/restored/`。项目应有清楚的启动入口：静态站点可以是 `index.html`；需要构建/服务的项目应包含依赖声明、源码、资源和启动命令。无需限制为单文件或特定框架。
- 同目录保留 `design_brief.md`，用于记录范围、页面区域、状态、实现决策和证据缺口。若资源或行为有重要替代，在 brief 或项目说明中列出来源与偏差，便于审阅。
- 用户明确要求 `--restore` 即授权生成最终项目；brief 是工作产物，不构成额外确认关卡。用户若明确要求“先看 brief 再实现”，则在该边界停下。

## 4. 对照验证

- 在目标视口运行项目，对照参考的首屏、滚动关键帧及指定交互状态；检查布局、文字、素材、裁切、动效与反馈。必要时逐项修正偏差。
- 走通关键导航/交互路径，检查资源请求、控制台错误、溢出和遮挡。响应式范围以参考或任务要求为准。
- 交付时说明启动方式、已复现范围、仍有差异的资源/状态及原因。不能把未实现的交互或静态替代描述成完整还原。
- 以 `scripts/restore/cli.mjs` 初始化 run，冻结页面、状态、视口、重点视觉 QA 与参考证据；按 ordinary/refined/complex 三档限制为 30/60/120 分钟有效执行时间、2/3/4 轮。额度或宿主中断造成的外部等待，取得起止时间证据后用 `time-exclude` 登记；正常工作仍计时。第 0 轮采集基线；每轮先写可证伪假设，再采集、比较和保留或回退。浏览器采集与模型评分按宿主能力接入；缺少 adapter 时保留未知，不编造分数。
- Loop 结束后由独立 E2E 模块对最终最佳版本按六维评分，不从三类 Loop 分数换算。T0–T4、brief 和 HTML 从结构化事实源生成，审批记录单独绑定报告；不会因 E2E 发现偏差而自动重新开启本次 loop。
- 可获得宿主或模型 API 的逐响应 token 用量时，按 [接口](restore/interfaces.md)用 `usage-record` 登记来源与覆盖范围；报告显示可归属总量及阶段拆分。缺失用量显示未知，不按对话长度估算。

## 完成判断

关键页面和状态可运行、目标区域有对应实现、可用资源已正确使用、核心交互可操作，并完成与参考的浏览器对照。若受证据或资源限制无法达到目标，明确指出未覆盖的范围和可复现的验证结果。
