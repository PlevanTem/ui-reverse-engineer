# 规格与验收

## 交付结构

默认输出 `motion-spec.md`；有条件时保存时间戳关键帧、差分图、采样记录等至相邻的 `motion-evidence/`，并在文档引用相对路径。用户指定输出路径或格式时优先使用。先写来源、采集环境、范围与覆盖清单，再逐条写规格，最后列未知项、待补证据和验收。不要创建空证据文件，也不要将示例数据当成真实取证。

覆盖清单至少列出：页面/片段与状态、触发或动作、已检查/不可达/未检查、证据索引；没有可访问样本时不可声称全覆盖。为重要路径列出顺序和依赖关系，避免将多阶段交互拆成互不相关的动画。

## 核心条目

每条仅需四个顶层字段：

- **名称**：稳定 ID + 组件/场景及动作，例如 `M01 · 导航菜单展开`。
- **用途**：观察到的功能与体验作用；目的不明确时标为推断或 unknown。
- **实现**：用可执行的描述记录触发与前置条件、对象/坐标系、起终状态及中间阶段、持续时间/延迟/顺序、曲线或动力学、空间/视觉属性、循环与滚动映射、完成/反向/中断/边界/响应式规则；不适用写 N/A，未证实写 unknown。指出目标环境等价实现建议和依赖条件，标记为建议。单位明确；状态值、时长、曲线分别区分观察、测量、推断。
- **参考依据**：证据 ID + 类型（运行时 / 操作观察 / 视觉测量 / 推断）+ 来源位置、复现步骤或视频时间区间 + 采集条件；关键参数能回溯到对应证据。对于视觉估计说明误差与采样限制；不同证据不一致时保留各自结果。

条目按“一个可单独触发或验收的行为”拆分；同步发生的多个对象应放在同一时间线上，描述相对偏移与依赖。共用 token 或时间线可引用，避免重复及相互冲突。实现建议不是已确认的源实现；不能仅写“类似参考”或贴一段源码。

## 示例（虚构，仅示范格式）

**M01 · 面板展开**

- **用途**：显示更多设置；承载辅助选择（后者为推断）。
- **实现**：点击设置按钮，关闭 → 打开；面板由高度 0 增至 120px，同时透明度 0 → 1。两项同时开始，200ms，`ease-out`；再次点击反向。按钮再次点击时中断规则 unknown。目标可用 CSS transition 实现（建议）。
- **参考依据**：E1 运行时记录 `panel-animation.json`，触发步骤为点击设置按钮；在 1440×900 视口下记录到时长 200ms 和 easing。E2 `motion-evidence/panel.webm` 00:00.000–00:00.400 观察到展开及反向；中断未测试。示例中的数字与文件均为虚构。

## 验收与交接

每条建立参考动作及复现路径、匹配环境、预期状态与可见变化、核对时间点和可测指标，以及通过条件。若无用户阈值，不编造固定的通用容差：列出待协商阈值或以对比观察报告差异。检查触发、时序、空间轨迹、曲线/速度趋势、联动、结束状态与反向/中断，适用时检查滚动和尺寸变化。实施后以相同视口、初始状态、输入、时间基准录制参考与目标对照，并分别记录通过、失败、无法判断；缺证据的项目为 unknown，不算通过。只交付规格时这些是待执行检查，不写成实际测试结果。
