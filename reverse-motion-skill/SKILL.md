# Reverse Motion Skill

将参考源中的交互、状态、时序、空间变化和动力学转化为可实现、可追溯、可检验的动效规格。先读取授权范围内可用的运行时证据，再通过真实操作和时间轴画面核对；视频或不可观测区域走视觉测量，不编造内部实现。只做分析与规格交付；实现、修改目标页面或外部发布需有相应任务授权。

## 边界与输入

接收网页 URL、可运行本地页面、视频/录屏、逐帧图像或它们的组合。确认目标页面、设备/视口、可访问路径、登录状态、可操作范围和参考时间段；用户未指定时按可访问范围开展并报告假设。执行方必须尊重任务的取证边界：例如已有 Restore run 的冻结输入及 `fixture_only` 白名单；没有授权时不得以本 Skill 绕过边界访问源码、运行时或额外参考。无法实际打开或分析源时，交付受限结果，不声称已提取。

## 工作流与决策图

先读 [动效逆向工作流图（含可编辑 Mermaid 源）](references/workflow.md)。图展示取证决策，不代表已有自动采集器；允许针对同一动效同时走多个机制分支。详细操作和局限见 [取证方法](references/capture.md)。

1. **定范围和优先级**：记录来源、可操作路径、视口、授权及限制；先探索用户主要路径、可见线索和显著动态区域，再按价值和剩余预算补充分支。列覆盖清单，区分已检查、不可达、未检查，标明停止原因；不把局部覆盖说成全站覆盖。
2. **按参考和状态选择路径**：可操作网页先布设可用监听与画面采集，再加载或触发；未触发时按优先路径操作，正在发生时连续采集，已结束时判断能否复位重现。无法重现则检查已留存证据和可访问规则，保留缺失。视频按时间轴分析；单张截图只支持可见静态状态；来源无法访问则报告阻塞。监听和录屏不是环境必有能力，无法使用时报告并采用可用替代。
3. **按可用机制交叉取证**：声明式、可访问库、脚本/滚动驱动、画布/视频或不可读取区域分别选择方法；机制不明则从行为与画面入手，必要时并行探索。不要因某一路为空就排除其他机制。采样动作前、中、后及可观察的反向和中断，标明任何干预。
4. **归纳与补证**：按动作对齐运行时、观察和画面证据，提取触发、状态、时序、空间、动力学及联动。关键证据缺失且有可行、在范围内的补证方式时定向复测；预算耗尽、无法访问或无新证据时停止，记录缺口，不循环假装已解决。
5. **交付与核查**：按 [规格与验收](references/spec.md) 输出 `名称 / 用途 / 实现 / 参考依据`、覆盖清单、未知项和待执行验收；事实、测量、推断和建议分开标注。对无法确认的数值用 `unknown` 或有依据的区间。只对明确范围评价覆盖；未实际执行实现或对照时不得报告已验证。

## 证据原则

- 已观察、计算/测量、推断、建议分别标注；每个关键参数链接到可重放操作、记录/文件位置或时间戳。证据与推断相互冲突时不覆盖证据。
- 运行时快照只说明采集时刻和可访问上下文；活动结束、未触发、隔离 frame/shadow、跨域和脚本逐帧更新都可能造成漏检。取不到参数不等于参数不存在。
- 视频可测的是帧采样下的画面变化；触发事件、真实缓动曲线、内部状态、屏幕外内容和源代码可能未知。区分帧间隔导致的时间不确定性及估算误差，不用抽样数据保证精确。
- 没有足够证据支持完整性或精准还原时，明确交付是部分规格，列出获取哪些补充证据能缩小差距。
